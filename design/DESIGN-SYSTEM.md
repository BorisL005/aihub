## §Aesthetic direction (owner-set, binding — designer agent may not edit this section)

AI Hub is a tool the owner opens twenty times a day for ten seconds, not a lifestyle
product. It should feel like professional software that respects the user's time.

**Reference anchors**
- **Revolut** — for confidence and density: strong typographic hierarchy doing the
  work color would otherwise do; numbers and dates as first-class citizens (tabular
  figures, generous size for amounts); flat surfaces; color used sparingly and
  semantically, not decoratively; dark-neutral chrome that lets content lead.
- **Jira mobile** — for utility: information-dense lists that stay scannable; status
  as small, consistent, text-labeled badges; unapologetically functional screens;
  navigation that is boring in the best way; nothing animated that doesn't inform.

**Adjectives**: dense, calm, utilitarian, confident, quiet.

**Anti-reference**: the averaged generative-AI look. If a screen would pass as a
mockup from a random "AI startup" template — gradients, glass, glow, oversized
rounded everything, purple-on-dark, decorative illustrations — it is wrong even if
it is pretty. When in doubt, remove decoration and strengthen hierarchy.

**Hard rules derived from the above**
- Two corner radii in the entire system (one for controls, one for sheets/cards). 
- Color palette: neutral base + one accent + semantic status colors. Nothing else.
- Typography does hierarchy; color does meaning; decoration does nothing.
- Motion only where it explains state change (progress, transitions). No delight animations.

# AI Hub — Design System

Baseline established on **KAN-5** (receipt photo capture). KAN-4 and everything after
inherit from here. This file is the contract between the design agent and the mobile

## 0. Derivation

Each choice below traces to one line of the direction. If a choice cannot be traced, it
is decoration and must be removed.

| Choice | Traces to |
|---|---|
| One typeface, hierarchy by weight and size | *"Typography does hierarchy"* — a second family would be decoration |
| Tabular figures everywhere a number appears | *"numbers and dates as first-class citizens"* |
| Zero-chroma neutrals | *"neutral base"* |
| Primary button in ink, not accent | *"color used sparingly and semantically"* — a button is hierarchy, not meaning |
| Accent only on progress, links, and the new-row tint | *"one accent"*, *"color does meaning"* |
| Exactly two radii, 6 and 12 | the hard rule, verbatim |
| No shadows; separation by hairline | *"flat surfaces"* |
| Dark-neutral camera chrome and toast | *"dark-neutral chrome that lets content lead"* |
| 64 px rows, 16 gutter, six rows visible | *"dense"*, *"information-dense lists that stay scannable"* |
| Badges small, rectangular, text-labeled | Jira mobile anchor, *"status as small, consistent, text-labeled badges"* |

## 1. Frame

| | |
|---|---|
| Baseline device | 390 × 844 (iPhone 14/15 logical) |
| Safe area | 59 top, 34 bottom — reserved, never painted into |
| Screen gutter | 16 — content gets the width |
| Entry row height | 64 (fixed), divider inset 68 to the text column |
| Button height | 48 primary/secondary, 44 quiet and nav |
| Minimum hit target | 44 (iOS HIG floor) |

The primary action of a screen lives in the bottom third, above the bottom safe area.
List rows are tappable across their full width. No fake status bar, no fake home
indicator, no fake keyboard: the OS paints those on top.

## 2. Colour

Neutral base at **zero chroma**, one accent, three semantic status hues. Nothing else.
Colours are authored in `oklch()`.

The accent is not a brand flourish. It is spent on three things only: the progress fill,
interactive text (back links), and the tint marking a just-added row. Everything that
looks like a button is ink.

| Token | Value | Use |
|---|---|---|
| `--bg` | `oklch(0.975 0 0)` | app background behind surfaces |
| `--surface` | `#ffffff` | lists, sheets, cards |
| `--sunk` | `oklch(0.945 0 0)` | inset wells, thumbnail backing, progress track |
| `--line` | `oklch(0.900 0 0)` | hairlines, row dividers |
| `--line-strong` | `oklch(0.800 0 0)` | secondary button border |
| `--ink` | `oklch(0.200 0 0)` | primary text **and primary button fill** |
| `--ink-muted` | `oklch(0.500 0 0)` | secondary text, quiet button label |
| `--ink-faint` | `oklch(0.650 0 0)` | annotation, empty-state icon |
| `--chrome` | `oklch(0.160 0 0)` | camera surface, toast |
| `--chrome-raised` | `oklch(0.240 0 0)` | raised element on chrome |
| `--on-dark` | `oklch(0.970 0 0)` | text and controls on chrome |
| `--on-dark-muted` | `oklch(0.720 0 0)` | secondary text on chrome |
| `--accent` | `oklch(0.520 0.160 252)` | progress fill, interactive text |
| `--accent-tint` | `oklch(0.960 0.025 252)` | just-added row |
| `--positive` | `oklch(0.500 0.130 150)` | read / done |
| `--positive-tint` | `oklch(0.955 0.030 150)` | |
| `--warn` | `oklch(0.520 0.110 70)` | waiting, or something the user must change |
| `--warn-tint` | `oklch(0.955 0.035 75)` | |
| `--danger` | `oklch(0.520 0.160 27)` | something failed, destructive action |
| `--danger-tint` | `oklch(0.955 0.028 27)` | |

Semantic colour is never the only signal — every status also carries a word.

Dark theme is **not** defined yet. First ticket that needs it defines it here.

## 3. Type

**IBM Plex Sans**, one family, fallback `system-ui`. Chosen because it was drawn for
dense technical software, holds up at 13 px in a packed list, and carries true tabular
figures. A second family would be decoration.

Every number — times, counts, percentages, amounts — is set
`font-variant-numeric: tabular-nums` so columns line up down a list.

| Style | Size / line / weight / tracking | Use |
|---|---|---|
| Display | 28 / 34 / 700 / −0.021em | screen title |
| Title | 22 / 28 / 700 / −0.018em | full-screen message headline |
| Heading | 17 / 24 / 600 / −0.01em | section, empty-state headline |
| Row | 16 / 22 / 600 / −0.008em | list row line 1, button label |
| Body | 15 / 21 / 400 | body copy, banner body |
| Label | 13 / 18 / 400 | list row line 2, hints, meta |
| Micro | 11 / 14 / 600 / 0.04em / uppercase | badges only |
| Amount | 19 / 600 / tabular | the number the user came for (KAN-6) |

## 4. Space and radius

Spacing steps: **4, 8, 12, 16, 20, 24, 32, 40, 56**. Nothing off the scale.

**Two corner radii in the entire system. A third is a defect.**

| Token | Value | Applies to |
|---|---|---|
| `--radius-control` | 6 | buttons, badges, thumbnails, chips, inputs, progress bar |
| `--radius-card` | 12 | sheets, cards, banners, toasts |

The camera shutter is a circle. That is geometry and a camera convention, not a third
corner radius — nothing else in the system is round.

Separation is by hairline, never by shadow. The only `box-shadow` permitted is
`inset 0 -1px 0` used to draw a row divider.

Sibling groups are laid out with flex/grid and `gap` — never margins between siblings.

## 5. Primitives

### Entry row
Fixed 64 tall, tappable full width, no chevron. Divider inset 68 so it starts at the
text column. Three slots, left to right:

1. 40 × 40 photo thumbnail, control radius
2. two-line stack — line 1 Row, line 2 Label muted with tabular figures
3. right slot, min-width 88, right-aligned

**The geometry does not change when extraction lands.** Before a receipt is read, line 1
is `Receipt`, line 2 is the time, and the right slot holds the status badge. After it is
read (KAN-6), line 1 becomes the merchant, line 2 stays the time, and the right slot
becomes the Amount style. Nothing reflows.

### Status badge
Height 20, padding 0 7, control radius, Micro type, tinted fill. Small and rectangular —
a pill would be a third corner radius. Maps from the receipt's stored status; the
internal name is never shown.

| Status | Label | Colour |
|---|---|---|
| `pending` | Not read yet | warn on warn-tint |
| `needs_review` | Needs a check | danger on danger-tint |
| `extracted` | Read | positive on positive-tint |

`extracted` normally hides the badge in favour of the amount; the badge exists for
surfaces that have no amount to show.

### Buttons
| Variant | Spec | Use |
|---|---|---|
| Primary | 48 tall, control radius, **`--ink` fill**, white 16/600 | the one thing to do on this screen — never two |
| Secondary | 48 tall, control radius, surface fill, 1px `--line-strong`, ink 16/600 | the alternative beside or under primary |
| Quiet | 44 tall, no fill, `--accent` or `--ink-muted` 15/600 | the way out of an error or a sheet |
| Quiet danger | as quiet, `--danger` label | destructive (Discard) |
| Disabled | 35% opacity, no colour change | |

Optional 18–20px stroke icon before the label, gap 8.

### Progress
One determinate bar, 6 tall, control radius, `--sunk` track, `--accent` fill. This is the
only place the accent fills a shape: it reports state, so it earns the colour. It only
ever moves forward. When a save spans several network calls the user still sees **one**
bar: it must not reset, restart or animate backwards between them.

### Message banner
Sits inside the bottom sheet above the action buttons, so cause and fix read together:
card radius, flat tint, no border, no shadow, 18px alert icon, headline 15/600 in the
semantic colour, body 14/20 in ink. `danger` for something that failed, `warn` for
something the user must change.

## 6. Rules

- **No dead ends.** Every error or blocked state offers at least one way forward and one
  way back.
- **Never imitate a system dialog.** Camera and photo permission prompts are the OS's.
  We may show our own rationale screen *before* handing off, and our own recovery screen
  *after* a denial — never a look-alike of the prompt itself.
- **One-handed.** Primary actions in the bottom third; rows tappable full width.
- **Motion only where it explains a state change.** Progress and screen transitions. No
  delight animation, ever.
- **Voice.** Short, plain, second person. Say what happened and what to do next. Never
  name the machinery — the user has *receipts* and *photos*, not entries, payloads,
  uploads or extractions.

| Say | For |
|---|---|
| Not read yet | a receipt with no fields read yet |
| Saving your receipt | save in flight |
| Receipt saved | receipt stored |
| Couldn't save that receipt | save or claim failed |
| This photo won't work | rejected before sending |
| Needs a check | `needs_review` |
